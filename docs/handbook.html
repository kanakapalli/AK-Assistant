Duck Keyboard

A macOS app that turns your voice into text, answers, Mac actions and meeting notes. Every model runs on the Mac itself; audio, questions and meetings never leave it.

Design principles

  • Private by construction. Speech-to-text, the chat model, the voice, speaker detection and summaries are local models. The only network traffic is downloading those models from Hugging Face.
  • Works from anywhere. The app lives in the menu bar and the Dock, starts at login, and its hotkeys work while any other app is in front.
  • Fast by default. Models are loaded in the background at launch and kept warm; speech is transcribed while you are still talking; answers are spoken sentence by sentence as they are written.
  • Standard Xcode project. Plain SwiftUI and the current observation APIs, no generated tooling, so it doubles as a learning project.

Getting started

Open the project in Xcode, let it fetch the Swift packages, pick a signing team and run.

Build and run

  1. Open AKAssistant.xcodeproj in the AK Assistant folder on the Desktop.
  2. Wait for Xcode to resolve the Swift packages (first time: several minutes). If it asks to Trust & Enable the MLXHuggingFaceMacros macros, allow it. If it reports a missing Metal Toolchain, install it from Xcode › Settings › Components.
  3. Select the AKAssistant target › Signing & Capabilities and choose your team.
  4. Press ⌘R. Onboarding opens on the first launch.

The project uses Xcode 16+ folder syncing (PBXFileSystemSynchronizedRootGroup): any file added to the AKAssistant folder, in Finder or Xcode, is part of the app automatically.

State and observation

  • AppState, Preferences, ModelManager and MeetingCoordinator are @Observable. Views read them through @Environment(Type.self); only views that read a changed property redraw.
  • Plumbing that isn't UI state (tasks, recorder handles) is @ObservationIgnored.
  • AppState.observePreferences() uses withObservationTracking to react to settings changes (new hotkeys, a different model) from anywhere in the UI.
  • The popup follows islandMode, computed from status, the dictation result, the AI reply and whether a meeting is recording.

1. The key

Modifier-only keys (Right ⌥ 61, Right ⌘ 54, Right ⌃ 62, Fn 63) are watched with global and local NSEvent .flagsChanged monitors, which need Accessibility. Custom combos use KeyboardShortcuts' key-down and key-up handlers. Esc while recording cancels. Double-tap detection for meetings lives here too (see Meetings).

2. Recording

  • AVAudioEngine taps the mic and converts each buffer to 16 kHz mono Float32 with AVAudioConverter. Nothing is written to disk.
  • The app you were typing in is remembered so it can be brought back to the front before pasting.
  • The speech model's load starts the moment the key goes down, in case it was unloaded.
  • Recordings stop on their own after 120 s.

3. Transcribing

Streaming models
Nemotron Streaming gets audio in ~0.1 s pieces while you talk; its running transcript is the live text, and only the last fraction of a second remains when you let go.
Other models
A live preview re-transcribes the recent audio about every 0.25 s (Parakeet, 20 s window) or 0.6 s (Whisper, 30 s window). When you let go, the whole clip is transcribed once more for the final text.
Skipped clips
Shorter than 0.3 s or with RMS below 0.004 (near silence), so Whisper can't invent “Thank you.” from nothing.

Engines implement one protocol, TranscriptionEngine (transcribe(samples, language)), with StreamingTranscriptionEngine adding beginStream / feed / finishStream. Backends: WhisperKitEngine, ParakeetEngine, NemotronStreamingEngine and, when the mlx-audio package is present, MLX engines. Each new load runs one second of silence through the model to compile its kernels before real use.

4. Cleaning up

PostProcessor.clean strips model artefacts such as [BLANK_AUDIO], removes filler words (“um”, “uh”) when that setting is on, collapses whitespace, fixes spaces before punctuation and capitalises the first letter.

5. Inserting

  1. Checks Accessibility and permission to post key events, and Secure Keyboard Entry (password fields, Terminal). If blocked, the text goes to the clipboard with the reason shown on the card.
  2. Accessibility insert: writes straight into the focused element of native apps and verifies the value changed. No clipboard involved.
  3. Clipboard + ⌘V: for browsers, Electron, Office and the rest. Waits for the hotkey's modifier to be released first so it can't combine with ⌘V. The previous clipboard is restored afterwards (after a delay, so slow apps read the new text first).

The result (inserted, pasted(focusConfirmed:) or copiedOnly(reason)) decides what the transcript card says.

6. History

Each dictation is saved as a DictationRecord (text, duration, model, app name and bundle ID). Retention: forever, 30 days, 7 days or don't save; old entries are pruned at launch and when the setting changes. Export as CSV or plain text.

The chat model

  • Loaded with #huggingFaceLoadModelContainer into an MLX ModelContainer; a ChatSession keeps the conversation.
  • Follow-ups within 5 minutes continue the same conversation; “New chat” or a longer pause starts fresh.
  • Generation: up to 500 tokens, temperature 0.7. Qwen3's thinking mode is turned off so answers start quickly.
  • The system prompt asks for short, spoken-style answers without markdown, since they may be read aloud.
  • The model loads in the background 2 s after launch (speech model first, then chat, then voice, one after another to avoid a memory spike) and unloads after 30 idle minutes.

The voice

  • Qwen3-TTS through Argmax TTSKit (Core ML). Nine speakers: Ryan, Aiden, Eric, Dylan, Serena, Vivian, Ono Anna, Sohee, Uncle Fu.
  • The voice opens before the answer arrives; each finished sentence is queued while the previous one plays, in one audio session so there are no gaps.
  • The speaker/language prompt prefix is cached on disk, which removes most per-sentence start-up work.
  • Pressing either hotkey while it's speaking stops the voice so the mic only hears you.

Mac commands

The AI key also acts on the Mac. Common phrasings are matched instantly and offline; anything else can still be turned into a command by the AI model.

How a phrase becomes an action

  1. CommandParser.parse matches the transcript against known phrasings and returns a MacCommand. No model needed.
  2. If nothing matches and Understand commands phrased any way is on, the chat model is told it may reply ACTION: <short English command>. The app holds back the streamed text until it can tell an action from an answer, then parses that phrase. This handles “fire up Apple's coding app” or “xcode kholo”.
  3. CommandRunner carries it out and returns done, answer (shown and optionally spoken), failed or notHandled (falls back to a normal AI answer).

Building blocks

AppFinder
Matches spoken app names against installed and running apps, with aliases (“vs code”, “chrome”, “settings”) and Levenshtein fuzzy matching (“ex code” → Xcode). Suggests close matches when unsure.
CommandRunner
Uses NSWorkspace, synthetic keys (media keys, ⌘⇧3, ⌃⌘Q), and through SystemControl runs osascript, pmset, mdfind, networksetup, caffeinate and shortcuts off the main thread.
TimerCenter
Voice timers and reminders; posts macOS notifications, plays a chime and shows a card when one fires. Cancel them from the menu bar.
ToolCatalog
The phrase list shown in Learn and given to the AI model as examples.

Risky actions

Quit an app, close a window or tab, lock, sleep, empty the Trash, Wi-Fi off, restart, shut down and log out. They run immediately by default. With Ask before risky actions on, the popup shows Run / Cancel, or you can hold the AI key and say “yes” or “no”. Restart, shut down and log out always show macOS's own confirmation too.

Dark mode, Empty Trash and restart/shut down/log out use Apple Events, so macOS asks once for permission to control System Events, Finder or loginwindow.

Starting and stopping

  • Double-tap the dictation key: both taps under 0.3 s, the second starting within 0.4 s of the first ending, and no other key pressed in between, so ⌥← word jumps never start a meeting.
  • A single press of the dictation key (or a double-tap) stops it. A second tap within 1 s of stopping is ignored, so a double-tap stop can't start a new meeting.
  • Also from the menu bar and the Meetings toolbar. Recording stops by itself after the configured maximum (default 4 hours).
  • While recording, dictation is paused and the AI key shows “Recording a meeting · press … to stop”.

Recording (MeetingRecorder)

Microphone
AVAudioEngine with Apple's voice processing (noise suppression and echo cancellation, as in FaceTime), other-audio ducking set to minimum. If macOS can't start it (error −10875, typically Bluetooth headphones or mismatched sample rates), the engine is rebuilt and the plain mic is used; the meeting gets a note.
The Mac's audio
ScreenCaptureKit stream with capturesAudio, excluding Duck Keyboard's own sound, 48 kHz stereo converted to 16 kHz mono. Video is set to 2×2 px at 1 fps and ignored. Needs Screen & System Audio Recording; without it the meeting continues mic-only.
Mixing
Every 0.25 s on a serial queue, the mic samples set the clock; Mac audio is added to them (zero-padded), and its backlog is capped at 1 s to absorb clock drift.
Files
<id>.m4a (mix, for playback), <id>-mic.m4a and <id>-mac.m4a (separate tracks on the same timeline, for the clean-up). AAC, 16 kHz mono, 32 kbps, about 15 MB per hour each, written as they record.
Chunks
From 18 s on, a piece is cut as soon as the last 0.4 s is quiet; at 28 s it's cut at the quietest 0.2 s between 15 s and 28 s.

Live transcript

Each piece goes through the selected speech model in order (pieces with RMS below 0.003 are skipped) and is saved straight away as a TranscriptSegment, so the Meetings screen fills in during the meeting and a crash loses at most one piece. It can be turned off to save battery when the clean-up pass is on.

Clean-up pass (MeetingCleanup)

  1. Speakers. FluidAudio's offline diarizer (pyannote segmentation, WeSpeaker embeddings, VBx clustering; about 30 MB downloaded the first time) splits the Mac track into Speaker 1, 2, 3… in order of first appearance. The mic track is “You”. With no Mac track (an in-person meeting), the mic track is split instead. An expected number of people can be set; the Mac track then gets that number minus one.
  2. Speech detection. Silero VAD finds speech in the mic track (and in the Mac track if speakers are off or fail), reading 10 minutes at a time to keep memory flat. Thresholds: Low 0.85, Normal 0.7, High 0.5; minimum speech 0.25 s, minimum silence 0.6 s.
  3. Transcription. Each piece of up to 25 s (longer turns are split at their pauses) is transcribed from its own track, with the dictation model or a bigger one picked in Settings.
  4. Echo filter. A “You” line is dropped when over half of it overlaps the others' speech and over 60% of its words also appear in what they said.
  5. Paragraphs. Consecutive lines from the same speaker less than 1.5 s apart are joined, up to a minute each.

If it fails, the live transcript is kept and the meeting shows why. Redo Clean-up and Speakers reruns it from the kept tracks and keeps names you already gave.

Notes (MeetingSummarizer)

  • A fresh one-off chat session (temperature 0.3) separate from the spoken conversation.
  • Transcripts over 2,500 words are summarised part by part first (700 tokens of notes each), then the notes are combined, so an hour fits a small model.
  • The model answers in a fixed format: TITLE, SUMMARY, KEY POINTS, DECISIONS, ACTION ITEMS with task | owner | due. The parser tolerates markdown and numbered lists, and keeps the raw text as the summary if the format wasn't followed.
  • Lines carry speaker labels, and the prompt says “You” is the person recording, so to-do owners come out right.
  • Detail: Brief (2–3 sentences, ≤4 points, 700 tokens), Standard (3–6 sentences, ≤8 points, 1,200 tokens), Detailed (2–3 paragraphs, 2,000 tokens).
  • Rewriting keeps to-dos you already ticked. An automatic “Meeting · date” title is replaced by the AI's title; one you typed is kept.

GPU (Core ML)
Loads quickly. The default for every model that offers it (Nemotron starts on the Neural Engine, since Core ML on the GPU runs its int8 weights about 10× slower).

MLX (GPU)

Custom models

Models › Add custom model accepts a Hugging Face WhisperKit variant (speech) or an MLX repo (chat), or a local folder / .zip link. They're stored as CustomModelRecord in UserDefaults and appear next to the built-in ones. Chat models can optionally keep “thinking” on.

Memory and loading

  • 2 s after launch the speech, chat and voice models load one after another.
  • The speech model unloads after 4 idle hours, the chat model after 30 idle minutes; both reload on the next use.
  • Switching a model in Settings or Models unloads the old one immediately.

Entitlements and Info.plist

  • com.apple.security.device.audio-input and com.apple.security.automation.apple-events, with the hardened runtime on.
  • NSMicrophoneUsageDescription: “Duck Keyboard listens only while you hold a hotkey or record a meeting you started, and transcribes on this Mac.”
  • NSAppleEventsUsageDescription explains the System Events, Finder and loginwindow use.
  • Not sandboxed: the App Sandbox blocks synthetic key events into other apps. Distribute with a Developer ID certificate and notarization, outside the Mac App Store.

What stays on the Mac

  • All audio, transcripts, questions, answers, meeting recordings and notes. They're processed by local models and stored in the locations listed under Architecture.
  • The network is used only to download models from Hugging Face (and FluidAudio's model repos).
  • Dictation audio is kept in memory only. Meeting audio is written to disk only for meetings, and can be deleted per meeting or not kept at all.
Permissions belong to one copy of the appmacOS grants Accessibility to a specific signed build. After rebuilding or moving the app, a row can look on in System Settings but not apply. Remove Duck Keyboard there with –, then add the current copy with +. Settings › Permissions shows the path of the running copy.

Troubleshooting & roadmap

Known problems with their fixes, then what's next.

ProblemFix
Hotkey does nothingCheck Accessibility in Settings › Permissions. After a rebuild, remove the app from Accessibility and add the current copy.
Fn opens the emoji pickerSystem Settings › Keyboard › “Press 🌐 key to” › Do Nothing.
Text isn't pasted in one appPassword fields and Secure Keyboard Entry block it; the text is on the clipboard. The card says why.
First dictation after launch is slowThe model compiles once on first load. On the Neural Engine this can take minutes; GPU is faster to load.
“Download … first”Download the selected model in Models.
Answers aren't spokenPick Show and speak or Speak only, and download a voice.
“Mic error … −10875” when starting a meetingVoice processing failed to start (often Bluetooth headphones). Current builds fall back to the plain mic and say “noise reduction off”. Use the built-in mic or wired headphones, or turn the noise setting off.
Meeting has only my voiceAllow Screen & System Audio Recording, then quit and reopen the app.
Meetings disappeared after reopeningAn older Duck Keyboard copy migrated the shared SwiftData file. Fixed by the private Meetings.store; replace old copies.
Speakers mixed upSet the number of people in Settings › Meetings, then Redo Clean-up and Speakers.
Something hangsPause in Xcode while it's stuck and check the main thread in the Debug Navigator. Logs: Console.app, subsystem com.natfirst.akassistant, categories Pipeline, Assistant, Insert, Meeting.
